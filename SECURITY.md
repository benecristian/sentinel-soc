# Security Policy & Threat Model Summary

## Purpose and Scope

**SENTINEL SOC** is a local, self-hosted security monitoring, threat detection, and incident response platform built for portfolio demonstration, detection-engineering study, and analyst workflow training.

All telemetry generated by the built-in Simulation Center is **100% synthetic** (`is_synthetic=true`), uses RFC 5737 documentation IP blocks (`192.0.2.0/24`, `198.51.100.0/24`, `203.0.113.0/24`) and RFC 2606 reserved domains (`.test`, `.example`), and never emits network packets or interacts with external systems.

---

## Implemented Security Controls

| Control Domain | Implementation |
|---|---|
| **Authentication** | Argon2id password hashing (`argon2-cffi`, RFC 9106 parameters) with constant-work verification against a pre-computed dummy hash when a username does not exist (mitigates timing-based user enumeration). |
| **Session Management** | Short-lived HS256 JWT stored in an `HttpOnly`, `SameSite=Strict` cookie (`sentinel_session`). Explicit algorithm allow-list prevents `alg: none` and algorithm-confusion attacks. User active status and role are re-verified from PostgreSQL on every request. |
| **CSRF Protection** | `SameSite=Strict` session cookie combined with a mandatory custom header (`X-Requested-With: SentinelSOC`) enforced on all state-changing methods (`POST`, `PATCH`, `DELETE`). |
| **Role-Based Access Control (RBAC)** | Three-tier model (`viewer` < `analyst` < `admin`) enforced via FastAPI dependencies (`app/api/deps.py`). Rule threshold and allowlist tuning require `admin`. |
| **SQL Injection Prevention** | SQLAlchemy 2.0 ORM and bound parameters exclusively. CIDR queries validate inputs through Python's `ipaddress.ip_network` before passing a bound parameter to PostgreSQL's `<<=` operator. Free-text `ILIKE` searches escape `\`, `%`, and `_`. |
| **Log & Stored XSS Prevention** | Log fields (URLs, user agents, usernames, command lines) are treated as untrusted attacker-controlled strings. They are rendered strictly as text in React (no `dangerouslySetInnerHTML`) and guarded by a strict `Content-Security-Policy`. |
| **PDF Markup Injection Prevention** | All event, alert, and note fields are XML-escaped (`xml.sax.saxutils.escape`) before being passed to ReportLab's `Paragraph` parser. |
| **Defensive File Uploads** | Extension allow-list (`.log`, `.txt`, `.json`, `.jsonl`), filename sanitization, streaming byte-size enforcement (`MAX_UPLOAD_MB`), NUL-byte rejection (blocks binary files), strict UTF-8 decoding, line-length and line-count caps. Uploaded files are parsed in memory as text and **never written to disk or executed**. |
| **Secret Management & Redaction** | No hardcoded secrets; startup fails fast if `SECRET_KEY` is under 32 chars or still holds `.env.example` placeholder text. `structlog` redaction processor masks keys matching `password`, `secret`, `token`, `authorization`, `cookie`, or `api_key`. |
| **Container Hardening** | Backend (`UID 10001`) and Frontend (`nginx-unprivileged`, `UID 101`) run as non-root users with `cap_drop: [ALL]` and `no-new-privileges:true`. |
| **Audit Trail** | Append-only `audit_logs` table records logins, failed logins, alert triage transitions, rule modifications, incident actions, and simulation executions. |

## Known Limitations (Honest Disclosure)

1. **Heuristic Detections Are Not Guarantees:** Rule-based thresholds and signatures have inherent false-positive and false-negative trade-offs. Determined adversaries can throttle below thresholds or obfuscate payloads.
2. **Single-Process In-Memory Rate Limiting:** `FixedWindowRateLimiter` stores counters in process memory. A multi-worker or multi-node deployment requires a shared store such as Redis.
3. **Synchronous Post-Ingest Detection:** Detection runs synchronously at the end of each ingestion batch. High-throughput production environments should decouple ingestion from detection using a message queue (e.g., Kafka/Redis Streams) and worker pool.
4. **Local HTTP by Default:** In local development (`docker compose up`), traffic on `127.0.0.1:8080` is HTTP so `COOKIE_SECURE=false` works out of the box. In `ENVIRONMENT=production`, startup enforces `COOKIE_SECURE=true` and requires TLS termination in front of the reverse proxy.
5. **No Multi-Factor Authentication (MFA):** Local accounts use single-factor password authentication.

## Reporting a Vulnerability

If you discover a security issue in this repository, please open a private security advisory on GitHub or contact the maintainer directly rather than posting an exploit in a public issue.
